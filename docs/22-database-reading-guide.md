# [과거 기록] DB 변경 파일을 쉬운 말로 읽기

DB는 회사·계좌·이체 내용을 앱을 꺼도 다시 찾을 수 있게 보관합니다.
테이블은 표와 비슷합니다. 한 행은 회사 한 곳 같은 대상 하나이고, 컬럼은 이름·금액 같은 항목입니다.
SQL은 DB에 "표를 만들어 줘", "이 행을 저장해 줘"처럼 작업을 요청하는 언어입니다.

## 파일은 왜 V1, V2로 나눌까요?

처음에는 회사 정보만 필요했지만 이후 사용자·계좌·이체 정보가 추가됐습니다.
이 변경 과정을 순서대로 기록한 파일이 마이그레이션 파일입니다. Flyway라는 도구가 적용 여부를 기록하고 새 파일을 순서대로 실행합니다.
이미 적용된 파일이 바뀌면 기존 DB와 새 DB가 서로 달라질 수 있어서, 파일 내용이 바뀌었는지도 검사합니다.
주석도 그 검사에 영향을 줄 수 있으므로 이번에는 SQL 원본을 수정하지 않았습니다.

| 파일 | 쉽게 말하면 |
| --- | --- |
| [V1](../src/main/resources/db/migration/V1__create_companies.sql) | 회사의 ID·이름·생성 시각을 보관할 표를 만듭니다. |
| [V2](../src/main/resources/db/migration/V2__create_app_users.sql) | 업무 사용자가 어느 회사 소속이고 어떤 인증 신원과 연결되는지 보관합니다. |
| [V3](../src/main/resources/db/migration/V3__create_accounts.sql) | 어느 회사의 계좌인지, 잔액이 얼마인지 보관합니다. |
| [V4](../src/main/resources/db/migration/V4__create_transfer_requests.sql) | 누가 어느 계좌에서 어디로 얼마를 보내려 하는지 보관합니다. |
| [V5](../src/main/resources/db/migration/V5__record_transfer_review.sql) | 기존 이체 요청 표에 결재자·결재 시각 칸을 추가합니다. |
| [V6](../src/main/resources/db/migration/V6__record_transfer_execution.sql) | 실행자·완료 시각 칸을 추가합니다. |

## 자주 나오는 SQL 표현

| 표현 | 뜻과 실제 예 |
| --- | --- |
| `CREATE TABLE` | 새 표를 만듭니다. `accounts`는 계좌 표입니다. |
| `ALTER TABLE` / `ADD COLUMN` | 기존 표의 구조를 바꿉니다 / 새 칸을 추가합니다. 기존 계좌에 입금하는 명령과는 다릅니다. |
| `PRIMARY KEY` | 행 하나를 구별하는 값입니다. 여기서는 UUID 형태의 id를 사용합니다. |
| `NOT NULL` | 값이 반드시 있어야 합니다. 이름이 빈 문자열인지까지는 별도로 검사해야 합니다. |
| `REFERENCES` | 다른 표에 실제로 있는 ID만 연결하게 합니다. 없는 계좌로 이체 요청을 저장하지 못하게 합니다. 이런 연결 규칙을 외래키라고 부릅니다. |
| `CHECK` | 저장할 값이 조건에 맞아야 합니다. `amount_won > 0`이면 0원과 음수를 거부합니다. |
| `UNIQUE` | 지정한 값 또는 값의 조합이 중복되지 않게 합니다. 사용자 표의 issuer·subject 조합에 사용합니다. |
| `DEFAULT` | INSERT에서 해당 칸을 생략하면 넣을 기본값입니다. 계좌 초기 잔액은 0입니다. |
| `BIGINT` | 큰 정수를 담는 자료형입니다. 원 단위 금액에 사용하며 무한히 큰 수를 담지는 못합니다. |
| `VARCHAR(100)` | 최대 100자 길이의 글자를 담는 칸입니다. |
| `TIMESTAMPTZ` | 시간대 정보를 고려해 시점을 저장하는 PostgreSQL 자료형입니다. 표시되는 시간은 접속한 세션의 시간대에 따라 달라질 수 있습니다. |
| `CREATE INDEX` | 특정 조건으로 찾기 위한 보조 구조를 만듭니다. 책의 찾아보기와 비슷하며 로그인 권한을 검사하지는 않습니다. |

## 예: 처리자와 시각은 둘 다 있거나 둘 다 없어야 합니다

V5에는 `(reviewer_id IS NULL) = (reviewed_at IS NULL)`이라는 조건이 있습니다.
`IS NULL`은 "값이 비어 있는가"를 묻습니다. 두 질문의 답이 같아야 하므로 다음처럼 됩니다.

| 결재자 | 결재 시각 | 결과 |
| --- | --- | --- |
| 없음 | 없음 | 허용: 아직 결재 전 |
| 있음 | 있음 | 허용: 결재 결과 기록 |
| 있음 | 없음 | 거부: 짝이 맞지 않음 |
| 없음 | 있음 | 거부: 짝이 맞지 않음 |

이 조건만으로 "승인 상태에는 반드시 결재자가 있다"까지 검사하는 것은 아닙니다.
현재 서비스와 엔티티가 상태 변경 시 두 값을 함께 넣습니다. V6도 실행자·완료 시각에 같은 짝 검사 규칙을 사용합니다.

V4의 상태 CHECK는 REQUESTED·APPROVED·REJECTED·COMPLETED라는 이름만 허용합니다.
"승인 없이 완료하면 안 된다"는 순서 검사는 Java의 TransferStatus와 서비스가 담당합니다.
또한 외래키는 ID의 존재만 검사하며, 그 계좌를 사용할 권한이나 로그인한 본인인지는 검사하지 않습니다.
